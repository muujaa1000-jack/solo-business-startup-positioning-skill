# Contributing

Thank you for improving this positioning Skill.

## Scope

Keep the positioning interview separate from commercial validation. Preserve
the one-question-at-a-time interview, the five information states, the four
candidate decision paths, and the seven-section final handoff unless a focused
behavior change is proposed and tested.

## Changes

- Inspect the current Skill and references before editing them.
- Add or update a contract test or evaluation before changing behavior.
- Keep examples fictional or composite; do not add real people, businesses,
  customer records, contact details, transactions, credentials, or local
  machine details.
- Label unsupported demand, payment, acquisition, and delivery claims as
  `待验证假设` or `未知`.
- Keep English and Chinese README sections in the same order.
- Run the repository tests that cover your change before opening a pull request.

## Pull requests

Explain the user-facing positioning behavior, evidence boundary, tests run, and
anything that remains unverified. Do not use a pull request to claim live host
compatibility or real market validation without dated, reproducible evidence.
